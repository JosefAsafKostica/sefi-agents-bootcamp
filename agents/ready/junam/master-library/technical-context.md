## רמה כללית — Basic (טירון)

**נימוק מבוסס דאטה:**
- **CLI Tools מותקנים:** רק `git` (מ-Apple) ו-`python3` (גרסת ברירת המחדל של Mac)
- **לא מותקן:** `node`, `npm`, `gh` (GitHub CLI), `docker`, `code` (VS Code) — כלומר אין סביבת פיתוח, אין virtualization, אין git CLI מתקדם
- **רקע ממפגש 1:** היה צריך הסבר מאפס על Terminal, git vs GitHub, Cmd+Shift+G — כל המושגים הבסיסיים
- **רקע ממפגש 3:** משתמש רק ב-ChatGPT, ברמת חיפוש מידע. לא בנה Custom GPTs, לא ניסה Claude, לא בנה אוטומציות.

זה לא טירונות "בלי פוטנציאל" — זה טירונות **של מקצוען בתחום אחר** (עו"ד מנוסה) שמכנס לראשונה לטריטוריה הטכנית.

## ניסיון Git / GitHub

**רמה:** בסיסית-מתפתחת.

**מה אסף יודע אחרי 3 מפגשים:**
- `cd`, `git init`, `git add .`, `git commit -m "msg"`, `git push`, `git status`, `git log`
- מה זה repository, מה ההבדל מ-GitHub
- שצריך Personal Access Token (PAT) ל-push (לא סיסמה)
- שצריך לשמור PAT בנושן ולא לחשוף ב-Terminal

**מה אסף עוד לא מכיר:**
- Branches, merge, pull request
- Conflict resolution
- Rebasing, stashing
- ניהול multiple remotes

**יעד עתידי:** בכל המסע ממשיך לעבוד עם git דרך **Terminal**, לא דרך MCP. זה כישור בסיסי שלא רוצים לאבד.

## ניסיון בכתיבת קוד

**אין.** אסף לא כותב קוד — הוא עורך דין. הוא מבין רעיונות טכניים, אבל לא מיישם אותם בקוד בעצמו.

## ידע API

**מעט מאוד.** אסף יודע מהמפגש הזה ש:
- API key = "סיסמה שמאפשרת לכלים לדבר עם השירותים שלי"
- צריך לשמור אותם במקום בטוח
- יש להם תפוגה ואפשר לבטל

הוא **לא** יודע איך לקרוא ל-API, לפענח JSON, לטפל בשגיאות, להגביל קצבים.

## חסם טכני עיקרי

**זמן, לא טכני.** אסף הצהיר במפגש 3:
> "יש לי בעיית זמן בעיקר כי אני עסוק ואני נוסע הרבה. אני מפספס שיעורים ואני לא יודע אם אני אצליח, אבל אני בכל זאת מוכן לנסות."

הוא לא חושש מ-AI. הוא חושש שלא יהיה לו זמן להתאמן ולהיתפס לקצב.

**משני (מעשי):** Terminal הוא עדיין מאתגר — לוקח לו רגע להתמצא, מבלבל בין פקודה לקלט (קרה שהוא הקליד טוקן כפקודה במקום כתשובה ל-prompt).

## סגנון למידה טכני

**ממפגש 3, מילולית:**
> "אני מעדיף גישה פרקטית, אבל כן עם הסבר שאני אבין. זה מאוד חשוב לי להבין. דוגמאות זה מצוין."

**פירוש:**
- **פרקטי קודם** — מה לעשות, צעד-צעד
- **הסבר קצר אחרי / תוך כדי** — למה זה ככה
- **דוגמאות קונקרטיות** — לא מופשט

## הוראות לג'ונאם (לעתיד)

### כשמציע פתרון טכני:
1. **התחל מהפעולה** — לא מההיסטוריה של הטכנולוגיה
2. **הסבר קצר אחרי** — שורה-שתיים על למה
3. **דוגמה קונקרטית** — לא רק תיאור
4. **ההנחה:** אסף לא יודע node/docker/אחר אלא אם תוודא במפורש
5. **בעבודה עם git:** דרך Terminal, לא דרך אינטגרציות
6. **כשמשהו חורג מהבסיסי** — תזהיר אסף ותסביר את הצורך להוסיף כלי/יכולת

### כש"אני לא מבין" עולה:
- אל תחזור על אותה תשובה
- חזור צעד אחורה
- תן דוגמה מהעולם של אסף (משפט, ניהול עסק) ולא מהעולם של מתכנתים

### כש-Terminal מבלבל את אסף:
- הזכר את ההבדל בין מצב "פקודה" (`%`) למצב "שאלה" (`Password for...`)
- זה היה חסם חוזר ב-3 מפגשים — חשוב לעטוף בלי לזלזל

### זמן הוא ערך:
- תמציתיות מעל אריכות
- 30 שניות שמועילות > 5 דקות שמסבירות
- אם משהו ארוך — תפצל לחלקים
